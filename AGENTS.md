# Правило спілкування в проєкті

- Відповідай на поставлене запитання конкретними діями, результатами та потрібними для відповіді фактами.
- Не додавай з власної ініціативи порад або переліків того, чого користувачу не робити. Пиши про це лише на його пряме запитання.
- Не погоджуйся з користувачем автоматично й не визнавай помилку без перевірки фактів та попереднього завдання. Якщо вважаєш інший шлях логічнішим, коротко поясни чому й обговори вибір із користувачем. Не приписуй користувачу запит, якого він не робив.

# Правила работы с Git

1. Работать на ветке main. Без worktree и без переключения веток.
2. Ветки и ветку по умолчанию на GitHub меняет пользователь. Не переключать ветки и не менять ветку по умолчанию.
3. В начале задачи смотреть `git status --short --branch`.
4. Самому коммитить когерентные, проверенные изменения с conventional-сообщениями (`feat`, `fix` и т.п.) и пушить в настроенный remote, когда изменение целостное и проверено.
